## The failure

Backend CI 44626688528 on main `c27890db` FAILED with exactly one test:
`test_download_endpoint.py::test_json_descriptor_has_a_handle_and_no_upstream_address`
(line 174): `assertEqual(body["stream_id"], token)` →
`'AnZlBGLO7RiyxcCW5nVz41Lt3Cm-' != 'AnZlBGLO7RiyxcCW5nVz402BjQc3'` — the JSON
descriptor returned a re-minted handle instead of the presented token.

## Root cause (proven, NOT the suspected R9×R10 interaction)

- `redact.mint_token` v2 packs `(id, expires_at)` with `expires_at = now + 86400`
  (second resolution). Same-second mints are equal; mints 1.5 s apart differ, sharing
  a long prefix and differing only in the tail — exactly the CI token pair's shape.
- `viewer.download_descriptor` ALWAYS re-minted
  (`token = redact.mint_token(int(source_id), signing_secret())`). The test mints
  before the request; the server mints after the resolve. Whenever the request
  crosses a second boundary, the descriptor returns a different token.
  Pre-existing race — the mint line predates R9/R10 by many commits
  (git log -S shows 6c8a919e, ffc3f5bc, dcee61a4). R9's recheck and R10's probe
  fallback never execute in this test's path (fresh temp DB → lookup miss →
  stubbed stage-2 probe). The merge run's slower runner just drew the unlucky
  second. Reproduced locally: the module passes solo (26 tests, 19.7 s) — the
  flake needs the second boundary.
- Same re-mint existed in the STREAM route descriptors: cache-hit branch and
  live-resolve branch, both `"stream_id": redact.mint_token(...)`. No test pinned
  the stream echo (`test_redact.py:1293` asserted only provenance/success/no-url).

## The fix (echo, not a test change)

- `download_descriptor(source_id, res, base_url="", token=None)`: if `token` is a
  valid signed handle for this source_id
  (`redact.parse_token(token, signing_secret(), signed_only=True) == int(source_id)`),
  echo it; else mint as today (operator-port plain-id path). The `signed_only=True`
  check matters: a plain row id must NOT be echoed (enumerable).
- Download route call site (the only caller): passes `token=source_ref` (the raw
  presented `id`; the descriptor is only built on the public port where
  `source_ref` is a validated handle).
- Stream route: both descriptor sites echo `source_ref` (defined at the branch
  top; both sites run only when `not full`).
- Left alone: the 302-branch `download_filename(mint_token(...))` (filename
  prefix only, cosmetic, no test pins it).
