# API-01 — IP-bound guard is real now (2026-11-24)

Branch `muse/phase4-api01-ipbound-20261124` from `ef15f2fc`.
Checkup F-01: the guard was dead code — nothing ever set `ip_bound=1`, so the
6 proven IP-bound hosts (mixdrop, vidhide, streamtape, voe, 1xplayer, mega)
were banked globally and served cross-IP, where they 403.

## What changed

- `host_classifier.py` — the per-host flag table (the single authority for
  hoster classification, per its own docstring). `IP_BOUND_LABELS` (service
  labels, incl. `pkembed` = mixdrop's embed label, same mxcontent final
  host) and `IP_BOUND_HOSTS` (final-URL host suffixes: `mxcontent.net`,
  `tapecontent.net`, `cloudwindow-route.com`, `cdn-centaurus.com`,
  `asrmo449ddj.com`, `userstorage.mega.co.nz`). `ip_binding_scope(url,
  service)` returns `"ip"` or `"/16"` (VOE only — its `i=` embeds the
  minting /16, 3 mints confirmed; the rest are proven bound to *an* IP with
  no wider scope measured, so exact-IP only, the fail-closed direction).
  Host first, label second, same evidence order as `classify`.
  `ip_matches_scope(scope, minted_ip, client_ip)` — exact match, or first
  two IPv4 octets for `/16`; unparseable fails CLOSED. A host is added only
  on probe evidence (same URL, two egresses, one 403).
- `resolved_cache.py` — `resolved_cache` gains `minted_ip TEXT` (NULL =
  pool/warm mint, or pre-guard row) with an ALTER migration in
  `_ensure_schema` for live DBs. `record_resolved_cache` stamps `ip_bound=1`
  at bank time: an explicit `ip_bound` in the resolve answer wins (the
  unwrapper's probe is fresher than the table), else the table decides by
  final-URL host then service label; unknown hosts stay NULL (untested),
  never 0. `minted_ip` is stored only on `ip_bound=1` rows, and only when
  the banker knows the pressing client's IP. The upsert keeps an existing
  `minted_ip` when a client-less (pool/warm) bank overwrites the row — a
  detail warm must not clobber the JIT mint a same-IP press can be served —
  and a JIT re-bank for another IP overwrites it. `lookup_cache` gains
  `client_ip`: a bound row serves only with `allow_ip_bound=True` AND the
  minting IP (VOE: same /16); opt-in alone no longer serves (that was the
  hole). Rows banked before the guard (`ip_bound` NULL) are re-derived from
  the final-URL host at lookup, so the live bank's existing IP-bound rows
  refuse too — they have no `minted_ip`, so they are never served. A stored
  `ip_bound=0` (a probe proved *this* URL not bound) outvotes the table.
  The hit never carries `minted_ip` out of the cache layer (provenance
  rule: no client IP in any response or log).
- `viewer.py` — `_press_client_ip(handler)` (`redact.client_ip`, the same
  per-user key the rate limiter uses; fault/unknown reads as no IP, never a
  guess). Both press routes pass it into `_servable_banked_hit`, which opts
  the lookup into same-IP serving, and stamp it onto a *copy* of the fresh
  resolve when banking. A refused bound row reads as a cache miss: the
  press re-resolves and fails over to the next verified candidate instead
  of 302-ing a token that 403s on this client. No other lookup caller
  changed: pool/warm/verify/api_v2 keep the default refusal (safe
  direction — a refused row just re-resolves).
- Orthogonal to `resolver-bank-defects` (tip `9f3cc4c4`, not in main): that
  branch touches the negative-cache skip + stillborn-expiry drop in
  `fast_fetch.py` and the 403 header-refusal in `serve_verify.py`; this
  branch touches none of those lines and does not bump `RESOLVER_VERSION`
  (no unwrap outcome changes, same as that branch).

## Owed / not claimed

- Whether a server-egress-minted token actually *plays* for the recorded
  client IP is unproven: the origin-map evidence binds the token to the
  minter's egress, and this guard partitions the bank per pressing client
  IP (the model the checkup prescribes: "resolve per client IP"). If a
  live egress-portability probe shows the token stays egress-bound even
  for the recorded client, same-IP serving still 403s in the player and
  the real fix is per-client minting (X-Forwarded-For at mint time) or a
  same-egress proxy — that probe is follow-up, not part of this branch.
  What this branch guarantees today: no banked IP-bound URL is ever 302'd
  to a different client IP, and every such press re-resolves + fails over
  to a non-IP-bound sibling instead of serving a known 403.
- No live writes, no gate/merge/restart, no live-tree touch. No
  `RESOLVER_VERSION` bump. No new test file (existing suites extended, so
  no CI-manifest change).
